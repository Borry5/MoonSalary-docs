## 一、三个冲突的处理结论

### ✅ 冲突 1：App 名称 —— 已定

**商店名称就用「打表上班」。** 文档仓库里的名称、关键词已全部同步。

> ⚠️ **但要留意一个副作用**：App **装到手机上显示的名字仍是「月薪鸭」**
> （工程里 `INFOPLIST_KEY_CFBundleDisplayName = "月薪鸭"`）。
> 商店页叫「打表上班」、桌面上叫「月薪鸭」，用户会困惑。
> 建议二选一：
> - 把 `CFBundleDisplayName` 也改成「打表上班」（需改代码 + bump 版本 + 重新归档上传）
> - 或者商店名称改回「月薪鸭 - 实时进账工资条」
>
> 保持不一致**不违反**审核指南，但会明显影响转化。

### ✅ 冲突 2：版本号 —— 已定

**把页面上的 `versionString` 填成 `0.2.19`**，与已编译好的构建版本一致。
零成本，不用重新构建。

> 若页面标题仍显示「iOS App 版本 1.0」，改完这个字段后标题会跟着变。

### ⏳ 冲突 3：截屏尺寸 —— 待处理

页面上的 iPhone 槽位写得很明确：

```
6.5 英寸显示屏
将最多 3 个 App 预览和最多 10 张截屏拖到此处。
(1242 × 2688px、2688 × 1242px、1284 × 2778px 或 2778 × 1284px)
```

**接受的尺寸只有这四个，没有 1320 × 2868。** 而我们现有的 iPhone 截图
全是 **1320 × 2868**（6.9 英寸），拖进去会被拒。

正在重新出图，**会同时产出 1284 × 2778 与 1320 × 2868 两套**：
前者喂给这个 6.5" 槽位，后者备用（万一页面上能找到 6.9" 的切换）。

## 二、逐字段填写

字段 `id` 是页面里的真实值，可用 `⌘F` 搜索定位。

### 1. `promotionalText` — 推广文本（上限 170）

> 可随时改，无需重新审核。

```
亮屏即见今日到手。把月薪换算成实时滚动的数字，摆在 iPhone 锁屏和 Mac 菜单栏上。支持双休/大小周/单休三种工作日口径，自动跟随中国大陆法定节假日与调休。数据只存在你自己的 iCloud 里。
```

字符数 **101**。

### 2. `description` — 描述（上限 4000）

直接粘贴文档仓库 `app-store/metadata.md` 里「描述」那一节的内容（约 620 字符），
包含：产品定位 / 锁屏小组件 / Mac 菜单栏 / 三种工作日口径 / 薪资三档联动 /
统计与日历 / iCloud 私密同步 / 关于隐私 / 关于算法。

### 3. `keywords` — 关键词（上限 100，英文逗号分隔，**逗号后不要空格**）

```
月薪,工资,工资条,收入,实时,进账,日薪,时薪,年薪,打卡,考勤,工时,加班,加班费,请假,日历,倒计时,锁屏小组件,桌面小组件,记账,退休,存钱,打工人
```

字符数 **76**。

> 名称从「月薪鸭 - 实时进账工资条」改成「打表上班」后，
> 名称里不再含「月薪 / 工资 / 收入 / 实时 / 进账」，所以这些词必须补进关键词。
> 另外补了「打卡 / 考勤 / 工时」——「打表上班」这个名字会吸引找考勤类 App 的用户。

### 5. `marketingUrl` — 营销网址

### 6. `versionString` — 版本

**填 `0.2.19`**（与已编译好的构建版本一致，见「冲突 2」）。

### 8. 构建版本

从 Xcode 上传（Organizer → Distribute App → App Store Connect → Upload）。

> 上传前记得先解决 **PLA 协议**那件事（App Store Connect 顶部横幅 Review/Agree）。

页面上的「需要登录」复选框**不要勾**。

**联系信息**（`contactFirstName` / `contactLastName` / `contactPhone` / `contactEmail`）

| 字段 | 建议填 |

macOS 版常驻菜单栏右上角，点击状态项展开面板。

### 10. 出口合规

页面提示：「如果你的 App 使用加密技术，你需要上传出口合规证明文稿」。

**不用管。** 我们已经在工程的 Info.plist 里声明了
`ITSAppUsesNonExemptEncryption = NO`（0.2.16 加的），
上传后这一节会自动通过，不会要求你交文稿。

### 11. App Store 版本发布

| 选项 | 说明 |
|---|---|
| 手动发布此版本 | 审核通过后由你手动点发布 |
| **自动发布此版本** | 审核通过后立即上架 |

首次上架**建议选手动发布** —— 留个缓冲，审核过了先自己看一眼商店页再放出去。

## 三、这一页之外的必填项

这一页只是「版本信息」。提交审核前，左侧栏这几个也要填完：

| 位置 | 要做什么 | 参考 |
|---|---|---|
| **App 信息** | 名称、副标题、主要语言、Bundle ID、SKU、主要分类 | `app-store/metadata.md` |
| **App 隐私** | 选「**否，我们不会从此 App 收集数据**」 | `app-store/privacy-answers.md` |
| **年龄分级** | 全部选「无」→ 结果 **4+** | `app-store/age-rating.md` |
| **价格与销售范围** | 免费、公开发布 | `app-store/metadata.md` |
| **App 审核 → 出口合规** | 已由 Info.plist 声明，无需操作 | — |
