# App Store Connect 填写指南（逐字段对照）

> 对照页面：`App Store Connect (2026_10_6 00：31：49).html`
> 即「iOS App 版本 1.0 · 准备提交」这一页。字段名取自页面里的真实 `id`，
> 方便你在浏览器里用 `⌘F` 定位。

## 一、⚠️ 三个必须先解决的冲突

这三条不解决，后面填得再对也提交不了。

### 冲突 1：App 名称对不上

页面左上角显示的应用名是 **「打表上班」**，而本文档仓库里准备的名称是
**「月薪鸭 - 实时进账工资条」**。整份页面里没有出现过一次「月薪鸭」或 `MoonSalary`。

**这意味着两种情况之一**：

- **情况 A**：这个 App 记录就是月薪鸭，只是你在创建时把名称填成了「打表上班」
  → 去 **「App 信息」** 页把「名称」改成 `月薪鸭 - 实时进账工资条`（30 字符上限，现为 13）
- **情况 B**：这是另一个 App 的记录，月薪鸭的 App 记录还没建
  → 先 **「我的 App」→ `+` → 新建 App**，Bundle ID 选 `borry5.MoonSalary`

**请先确认是哪种。** 如果是情况 A，名称一改就继续往下走。

### 冲突 2：版本号对不上（**会直接卡住构建版本**）

| | 值 |
|---|---|
| 页面 `versionString` 字段当前值 | **`0.1.0`** |
| 页面标题 | `iOS App 版本 1.0` |
| 我们编译出来的构建版本 | **`0.2.19`** |

App Store Connect 要求**这里填的版本号与上传的构建版本号完全一致**，
否则「构建版本」那一栏里根本选不到你的包。

两条路，**选一条**：

| 方案 | 做什么 | 代价 |
|---|---|---|
| **① 改这里**（推荐，零成本） | 把 `versionString` 填成 **`0.2.19`** | 无。App Store 上显示 0.2.19 |
| ② 改 App | 把工程的 `MARKETING_VERSION` 改成 `1.0`，重新编译 + 重新归档 + 重新上传 | 要重跑一遍构建，且打破「只递增第三位」的约定 |

> 首次上架用 `1.0` 是惯例，但你定的规则是「只递增第三位、绝不跳 0.2.x」。
> 两条都合理，看你想要哪个数字出现在商店页上。

### 冲突 3：截屏尺寸对不上（**会直接拒收**）

页面上的 iPhone 槽位写得很明确：

```
6.5 英寸显示屏
将最多 3 个 App 预览和最多 10 张截屏拖到此处。
(1242 × 2688px、2688 × 1242px、1284 × 2778px 或 2778 × 1284px)
```

**接受的尺寸只有这四个，没有 1320 × 2868。** 而我们现有的 iPhone 截图
全是 **1320 × 2868**（6.9 英寸），拖进去会被拒。

两个选择：

- **A**：页面上如果有尺寸切换（找找「6.9 英寸」这类标签或下拉），切过去，用现有的 1320×2868
- **B**：按这个槽位的要求，重新出 **1284 × 2778** 的图（我正在做的那批会一并出这个尺寸）

## 二、逐字段填写

字段 `id` 是页面里的真实值，可用 `⌘F` 搜索定位。

### 1. `promotionalText` — 推广文本（上限 170）

> 可随时改，无需重新审核。

```
亮屏即见今日到手。把月薪换算成实时滚动的数字，摆在 iPhone 锁屏和 Mac 菜单栏上。支持双休/大小周/单休三种工作日口径，自动跟随中国大陆法定节假日与调休。数据只存在你自己的 iCloud 里。
```

字符数 **101**。

### 2. `description` — 描述（上限 4000）

直接粘贴文档仓库 `app-store/metadata.md` 里「描述」那一节的内容（约 620 字符），
包含：产品定位 / 锁屏小组件 / Mac 菜单栏 / 三种工作日口径 / 薪资三档联动 /
统计与日历 / iCloud 私密同步 / 关于隐私 / 关于算法。

### 3. `keywords` — 关键词（上限 100，英文逗号分隔，**逗号后不要空格**）

```
薪资,日薪,时薪,年薪,打工,上班,倒计时,锁屏小组件,桌面小组件,记账,日历,请假,加班,退休,存钱,目标
```

字符数 **54**。

> 「月薪、实时、进账、工资、收入」不用重复写 —— Apple 会把应用名称和副标题一并索引。

### 4. `supportUrl` — 技术支持网址

```
https://borry5.github.io/MoonSalary-docs/support/
```

### 5. `marketingUrl` — 营销网址

```
https://borry5.github.io/MoonSalary-docs/
```

### 6. `versionString` — 版本

见「冲突 2」。**填 `0.2.19`**（或你决定改成 1.0 后填 `1.0`）。

### 7. `copyright` — 版权（上限 200）

```
© 2026 Bo Meng
```

### 8. 构建版本

从 Xcode 上传（Organizer → Distribute App → App Store Connect → Upload）。
上传后等 TestFlight 处理完（几分钟到半小时），这里才会出现可选的构建版本。

> 上传前记得先解决 **PLA 协议**那件事（App Store Connect 顶部横幅 Review/Agree）。

### 9. App 审核信息

**登录信息**（`demoAccountName` / `demoAccountPassword`）

**留空。** 月薪鸭没有账号体系，不需要登录。
页面上的「需要登录」复选框**不要勾**。

**联系信息**（`contactFirstName` / `contactLastName` / `contactPhone` / `contactEmail`）

| 字段 | 建议填 |
|---|---|
| 名字 | `Bo` |
| 姓氏 | `Meng` |
| 电话号码 | `19315879918` |
| 电子邮件 | `borrymeng5@126.com` |

（这三个值来自你账号资料，Apple 默认也会预填。）

**备注**（`notes`）

粘贴 `app-store/review-notes.md` 的内容，核心几句：

```
本 App 无账号体系、无服务器、无网络账号需求，可直接使用。

锁屏小组件的测试方式：在 iPhone 锁屏上长按 → 自定 → 添加小组件 →
找到「月薪鸭」，选「今日到手」矩形或行内样式。

App 会访问 cdn.jsdelivr.net 与 raw.githubusercontent.com 拉取公开的
中国大陆法定节假日数据集，请求只带年份、不带任何用户信息。
若网络不可达，App 会退回内置缓存，功能不受影响。

macOS 版常驻菜单栏右上角，点击状态项展开面板。
```

### 10. 出口合规

页面提示：「如果你的 App 使用加密技术，你需要上传出口合规证明文稿」。

**不用管。** 我们已经在工程的 Info.plist 里声明了
`ITSAppUsesNonExemptEncryption = NO`（0.2.16 加的），
上传后这一节会自动通过，不会要求你交文稿。

### 11. App Store 版本发布

| 选项 | 说明 |
|---|---|
| 手动发布此版本 | 审核通过后由你手动点发布 |
| **自动发布此版本** | 审核通过后立即上架 |

首次上架**建议选手动发布** —— 留个缓冲，审核过了先自己看一眼商店页再放出去。

## 三、这一页之外的必填项

这一页只是「版本信息」。提交审核前，左侧栏这几个也要填完：

| 位置 | 要做什么 | 参考 |

| **App 审核 → 出口合规** | 已由 Info.plist 声明，无需操作 | — |
